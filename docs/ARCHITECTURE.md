# «АЛИБИ» — архитектура и дизайн-документ

> Рабочее название проекта: **«АЛИБИ»** (сменится в одно месте — `GAME_TITLE`).
> Жанр: классический арканоид (brick breaker).
> Формат: веб-игра, HTML5 Canvas + TypeScript. Мобильный браузер — приоритет №1.
> Дата: 2026-11-07 · Статус: **черновик для утверждения** (до первой строки кода игры).

---

## 0. Что это и что важно

**Суть**: игрок — «наблюдатель», который разбивает улики-кирпичи, пока не соберёт общую картину дела.

**Правила от пользователя (всё, что нельзя нарушать):**

1. Геймплей — **классический арканоид**. Без «персонажей вместо шара/ракетки». Ракетка — просто платформа снизу. UI — базовый, как в обычной аркаде.
2. Вселенная — **атмосфера и отсылки**, а не прямые участники. Цвета, фон, детали, тексты, имена — да. Но никто не *играет роль* мяча.
3. **Слово «Менталист» не используется нигде** — ни в названии, ни в меню, ни в коде UI. Замаскировать ещё сильнее.
4. **Кровавый Джон** — да. Отдельный босс-уровень в конце. И его ухмылка на экране проигрыша.
5. Кадры — **пиксельные портреты, нарисованные кодом** (не реальные фото, не чужие ассеты).
6. Язык — **русский**.
7. **На мобилке должно быть прям хорошо.**

**Бонусы/пауэры — ДА, в v1** (решение пользователя, 2-я итерация): мультимяч, расширение ракетки и др. — см. §4.6.  
**Публикация** — статический сайт на **GitHub Pages** (авто-деплой из Actions) — см. §16.

## 1. Платформа и технологии

| Решение | Обоснование |
|---|---|
| **TypeScript + Canvas 2D** | Никаких тяжёлых движков. Вся игра — наш код, полный контроль над пиксельной графикой и мобильным вводом. |
| **Vite** как сборщик/dev-сервер | Быстрый старт, HMR, простой `npm run build` в статику. |
| **Нулевой бандл-арт**: спрайты — код (маски пикселей) или PNG, сгенерированные скриптом | Пиксель-арт по мотивам не требует лицензий, цельный стиль. |
| **Web Audio API** (или крошечная обёртка) | Звук без внешних файлов на старте: синтезированные короткие blip'ы; позже — файлы. |
| **localStorage** | Рекорды, настройки, текущая партия (resume). |
| Без фреймворков UI (React и т.п.) | Меню — тоже Canvas-экраны, единый стиль, меньше зависимостей. |

**Целевые браузеры**: iOS Safari 16+, Chrome Android, Safari/macOS, Chrome/Firefox desktop.  
Приёмы: `CanvasImageSource` — обычный canvas; никаких `OffscreenCanvas` только там, где есть fallback (Safari поддерживает, но проверяем).

## 2. Резолюция и масштабирование (фундамент «хорошо на мобилке»)

**Логический мир игры — фиксированная «пиксельная сцена»: `FIELD_W = 240 × FIELD_H = 320`** (портрет, 3:4).  
Всё рисуется в этих координатах на маленьком offscreen-canvas, затем увеличивается **целочисленно** (`Math.floor` масштаб) на экран — поэтому пиксели остаются чёткими и без мыла.

```
canvas-css-W = S * FIELD_W
canvas-css-H = S * FIELD_H
S = max(1, floor(min(availW / FIELD_W, availH / FIELD_H)))
```

- **HUD** — не внутри `FIELD`, а отдельной полосой сверху CSS (DOM-слой или второй canvas), чтобы масштаб поля не зависел от высоты HUD.
- **Safe area**: используем `env(safe-area-inset-*)` через CSS `padding` контейнера; работаем в `viewport-fit=cover`.
- **Orientation**: основной режим — **портрет**. В ландшафте: если ширина экрана ≥ 700px CSS — можно играть с полем по центру и подсказкой «поверните телефон»; иначе — оверлей «поверните телефон вертикально» (чтобы не биться об «широкий перевёрнутый телефон»).
- **DPR**: canvas backing store = `S * FIELD_W * min(devicePixelRatio, 2)` только при рендере UI-текста векторной подложки. Для пиксельной сцены — **строго без DPR**, `imageSmoothingEnabled = false`.
- **Горячая замена при resize/rotation** с пересчитыванием S и перерисовкой — без перезапуска партии (сохраняем позиции в логических координатах).

## 3. Управление

### 3.1. Мышь / тачпад (desktop)
- **Ракетка следует за мышью по X** (без клика). Кнопка не нужна.
- Клавиатура: ←/→ или A/D, **пробел** — запуск мяча / пауза.

### 3.2. Тач (приоритет)
Три режима, выбираемые автоматически:
1. **Drag (главный)**: касание в любом месте игрового поля **takes control**: ракетка привязана к пальцу (палец не обязан быть на ракетке). Хват пальца в поле → ракетка с центром под пальцем. Перевод абсолютный (не относительный) — это самый предсказуемый вариант для арканоида.
2. **Тап** — запуск мяча / пропуск меню.
3. **Отпускание пальца** ракетку не сбрасывает (она остаётся последней).

**Критично для мобилки:**
- **Управление только в нижней зоне** (нижние 45% экрана) — это и есть «зона большого пальца». Касание выше зоны не двигает ракетку (случайный палец сверху не путает).
- **Finger offset**: ракетка ставится так, чтобы её центр совпал по X с пальцем; **по Y пальца не ориентируемся**. Дополнительно `pointerType === 'touch'` (а не 'mouse').
- **Multi-touch**: поддерживаем **два пальца одновременно** (две ракетки? Новое — делаем как «сквозное касание»: только первый активный палец управляет; касание второго — пауза по тапу в панель). Т.е. **один активный pointer**, остальные игнорируются.
- **`touch-action: none`** на canvas, `overscroll-behavior: none`, `user-select: none`, `-webkit-tap-highlight-color: transparent` — чтобы свайп не обновил страницу и не выделял текст.
- **Haptic**: `navigator.vibrate` там, где доступно (Android), на удары/потере жизни (коротко, ≤ 30 мс, опция в настройках).
- **Кнопки** HUD на телефоне — ≥ 44×44 CSS px.

### 3.3. Полировка (на потом, в бэклоге)
- «Мягкая палка»: лёгкая инерция ракетки (anti-jitter) — 1 кадр сглаживания, без «плавания».
- Настройка «чувствительность» в меню.

## 4. Геймплейные системы

### 4.1. Физика и тик

- **Fixed timestep 1/120 с** для физики + интерполяция для рендера (аккуратный отскок на 120 Гц). На мобилках с 60 Гц всё равно 120 физических шагов — стабильность.
- **Комната**: поле ограничено стенами слева/справа/сверху; снизу — **без стены** (потеря жизни).
- **Мяч**: круг r = 2.5 логических px; скорость |v| = 78 px/с на старте, ×1.03 каждые 12 ударов по кирпичам, потолок 150 px/с. **Подбрасывание при старте** — 55–125° от горизонтали, знак X случайный.
- **Отскок от ракетки** — **не «угол по нормали», а «управляемый угол»**: точка попадания t ∈ [−1, 1] → новый угол: `θ = 60° * t` (до ±60°). Мяч после отскока всегда летит вверх. Это классика, понятная новичку и даёт контроль.
- **Против «застревания»**: после N=4 подряд отскоков от ракетки без контакта с кирпичом — принудительный сдвиг угла на ±8° (анти-«горизонтальная пылилка»).
- **Broadphase**: кирпичи в сетке — проверяем только окрестность текущей ячейки мяча (swept-AABB по X затем Y), O(кол-во в пользу); максимум кирпичей на уровне ~100 — тривиально.
- **Туннелирование**: скорость ограничена < половины высоты кирпича (6 px) за шаг — при шаге 1/120 и скорости 150 px/с за шаг 1.25 px — безопасно. Для ракетки — проверяем «мяч был выше, стал ниже» (сегмент vs AABB).

### 4.2. Сущности и состояния

```
Field: walls, paddle, balls[], bricks[], drops[*], boss
Paddle: x, w, h=4, y=H-9; paddle.halfW; move(x)
Ball: p, v, r, trail[], alive, stuck (прилип к ракетке при старте)
Brick: cell(cx,cy), type, hp, alive, flashT; grid index
Drop: x,y,vy,type — (задел на бонусы; v1 отключёно)
Boss: см. §9
```

**Game state** (FSM):
```
BOOT → TITLE → READY → PLAYING ⇄ PAUSED
                           ↓ (все кирпичи уровня)
                        LEVEL_CLEAR → (если босс-этап) BOSS_ROUND → ...
                           ↓ (жизни 0)
                        GAME_OVER → TITLE | READY
```

### 4.3. Счёт и комбо

- Очки: кирпич типа T = `10 + 5*T` (T=1..5).
- **Комбо**: серия ударов по кирпичам без касания ракетки, **сбрасывается при касании ракетки или потере мяча**. Множитель: 1..2..4..8 (шаг каждые 4 удара, максимум ×8). Очки = `(10 + 5*T) * multiplier`. Комбо крупно флашится в HUD, когда ≥ ×2.
- **Особый визуальный бонус**: 5 подряд → тонкая красная «нить» на HUD (лёгкая отсылка).

### 4.4. Жизни

- 3 жизни. Потеря мяча → если `balls.length == 0` → жизнь −1, если 0 → `GAME_OVER`.
- При потере жизни HUD кратко подсвечивает «сердечки» красным (стиль детективного табло), короткая вибрация/звук.
- Жизни отображаются как маленькие **перфокарточки/карманные часы**, не как сердца (стиль).

### 4.5. Пауза, авто-пауза

- Пауза: кнопка в HUD (44×44) и `space`/`Esc`.
- **Авто-пауза** при `visibilitychange`/`blur` (важно для мобилки — пришёл звонок, не терять мяч) — включается по умолчанию, настройка в опциях.
- Запоминание выбранной паузы/партии в localStorage (resume).

### 4.6. Бонусы (пикапы) — v1

**Как появляются**: при разрушении кирпича с вероятностью **12%** (настраивается на уровне `dropChance`) выпадает «улика» — маленькая капсула-конверт, медленно (48 px/с) падает вниз. Поймал ракеткой → эффект. Не поймал за пределы поля → пропал. Одновременно на поле не более **3** дропов.

> **Оформление**: бонусы выглядят **не как буквы, а как предметы** (папка, фото, чайник, помада, зеркальце, часы, ножницы), есть **легенда в меню «Как играть»** — иначе на телефоне с мелкими предметами буквы нечитаемы.

| # | Предмет (стиль) | Эффект | Длительность | Редкость |
|---|---|---|---|---|
| 1 | **Папка дела** (архивная картонка) | **Мультимяч**: из текущего мяча вылетают ещё 2 (макс. 6 мячей) | мгновенно | частая |
| 2 | **Фото-улика** (ежедневка в рамке) | **Расширение ракетки** ×1.6 | 15 с | частая |
| 3 | **Чашка с кофе** (как в конторе) | **Слоу-мо** на 3 с (мяч двигается медленнее, управление плавное) | 3 с | редкая |
| 4 | **Ножницы** | **Стрижка**: −1 HP у всех кирпичей в радиусе 40 px вокруг места падения | мгновенно | редкая |
| 5 | **Помада** | **Платформа-страховка**: ракетка на 8 с становится шире и «липнет» (мяч задерживается) | 8 с | редкая |
| 6 | **Часы** | **+1 жизнь** (макс. 5) | мгновенно | очень редкая |
| 7 | **Зеркальце** | **Захват мяча**: мяч прилипает к ракетке до тапа/пробела (удобно на телефоне) | до сброса | редкая |
| 8 | **Голова-ухмылка (маленькая, злая)** | **Проклятие**: ракетка сужается на 10 с + толчок по цвету экрана — заставляет играть внимательнее | 10 с | редкая (на 3-й главе чаще) |

**Правила конфликтов:**
- Одинаковые эффекты **не стакаются** — продлевают таймер (макс. 2× длительности).
- «Расширение» и «страховка» — один и тот же модификатор ширины; совместно ограничение: `width = base * 1.6`, таймеры независимы, побеждает более длинный.
- Мультимяч при уже 3+ мячах — добавляет только 1 новый (не заливает экран).
- Слоу-мо не замедляет таймеры других бонусов (иначе «вечный» мультимяч).

**Отображение активных эффектов** — строка иконок под HUD (пиксель-иконки 8×8 + убывающая полоска), это важно для читаемости на мобилке. Одновременно максимум 4 иконки, остальные — в порядке убывания таймера.

**Баланс**: бонусы считаются «счастливыми уликами» — в очки они не дают ничего; риска подбирать вредный бонус нет, кроме злого (редкий, заметно жёлто-красный). Мультимяч — главный «интерес» геймплея.

## 5. Данные уровней (JSON) и «редактор»

### 5.1. Формат

`levels.json` — **массив глав**:

```json
{
  "meta": { "version": 1, "fieldW": 240, "fieldH": 320, "brickCols": 12, "brickRows": 22 },
  "chapters": [
    {
      "id": "ep1",
      "title": "Дело о выбеленных стенах",
      "palette": "ep1",
      "levels": [
        {
          "id": "e1-01",
          "title": "Ход 1",
          "rows": [
            "....1111....",
            "..11222211..",
            ".1123332211.",
            "112233332211",
            ".1123332211.",
            "..11222211.."
          ],
          "legend": { "1": "archive", "2": "stone", "3": "blood" }
        },
        {
          "id": "e1-boss",
          "type": "boss",
          "title": "Ход финальный",
          "boss": { "hp": 30, "pattern": "grin", "shields": ["....1111....", "...112211..."] }
        }
      ]
    }
  ]
}
```

- **Символы сетки**: `.` — пусто; `1..5` — тип кирпича; `X` — неразрушимый кирпич; `G` — «стекло» (1 удар); `?` — «конверт с уликой» (спецтип, см. §7).
- `legend` переопределяет символы на типы; по умолчанию `1=archive, 2=stone, 3=blood, 4=lamp, 5=gold`.
- **Валидатор в CI/при загрузке**: размеры сетки, известные символы, тип босса. Ошибка → консоль + fallback (уровень пропускается с логом).
- **Сложность**: `speedScale` на главе; `lives` на игре.

### 5.2. Мини-редактор (dev-only)
`/editor.html` — страница, где можно **кликать по сетке** и получать JSON (простой: `<textarea>` с JSON справа, сетка слева). Не входит в прод-бандл. Цель — быстро нарисовать 20 уровней.

```
│   ├── render/
│   │   ├── Canvas.ts     # логический offscreen → экран, fitScale(), resize
│   │   ├── Pixel.ts      # маски-спрайты, blit, палитры

│   │   ├── background.ts # прожектор, сетка, сцена-подиум
│   │   └── hud.ts        # методом CSS/второй canvas
│   ├── input/
│   │   ├── Input.ts      # Pointer Events: mouse/touch/pen, зона пальца, drag
│   │   └── Keyboard.ts
│   ├── audio/
│   │   └── Sfx.ts        # синтез (Web Audio), unlock по первому тапу
│   ├── data/
│   │   ├── levels.json
│   │   └── strings.ru.ts # ВСЕ тексты (задел на второй язык)
│   └── storage/
│       └── Save.ts       # localStorage: record, settings, progress
├── editor.html + src/editor.ts  (dev только)
├── index.html
├── package.json  tsconfig.json  vite.config.ts
└── README.md
```

**Принципы:**
- **Один источник правды**: `Game` владеет состоянием; «системы» — чистые функции/классы, не трогают DOM.
- **`constants.ts`** и **`data/strings.ru.ts`** — всё настраиваемое.
- **`palette.ts`** — все цвета (главы) в одном месте: перекраска вселенной = правка одного файла.
- **`systems/Powerups.ts`** — реестр бонусов: `{ id, sprite, weight, duration, apply(ctx) }`; добавить новый бонус = одна запись + спрайт.
- **Строка «Менталист» отсутствует** в исходниках (в т.ч. ни в комментариях) — держим этот документ и код в чистоте от слова.
- Рендер **не считает физику**; физика **не знает** о canvas.

## 7. Визуальный дизайн

Подробнее — раздел 9 (макеты) и `docs/images/`.

### 7.1. Стиль
**Ретро-пиксель 8–16 бит**, тёмная «сцена», тёплый свет и красные акценты.  
Пиксельная сетка базового разрешения 240×320; все элементы кратны пикселю; **без сглаживания**; лёгкая 1-px рамка по краю экрана (как старые игры).

### 7.2. Палитра (глобальная)

| Роль | HEX | Комментарий |
|---|---|---|
| Фон глубокий | `#070613` | почти чёрный, сине-фиолетовый |
| Фон сцены | `#0d0a20 → #201640` | градиент вверх-вниз |
| Прожектор | собрать из `#3a2b68` с прозрачностью | свет «от стола» — ключевой элемент |

**Детали:** 1-px светлая верхняя/левая грань, тёмная нижняя/правая, 2 «заклёпки», лёгкая трещина. При HP>1 — дополнительные тёмные пиксели-трещины по мере урона. При попадании — белая вспышка кадра (4 фрейма) и 3–5 частиц цвета кирпича.

### 7.4. Ракетка
Массивная тёмно-серая **«полированная ручка»** (пульт/дело в папке) длиной 48 px (4 px высотой): светлый верх, тёмный низ, две золотые «кнопки». При попадании — светлый блик секундой.

### 7.5. Шар
4-px «яйцо-свет»: кремовое ядро + белая точка, короткий шлейф из 2 затухающих пикселей (не линия, не glow — оставить «ретро»).

### 7.6. Фон и сцена (это то, что делает вселенную)
1. **Вертикальный градиент** тёмно-синего.
2. **Прожектор** — мягкий конус света сверху (пиксельная дизеринг-градация, 26 ступеней, с прозрачностью). «Правду видно в свете».
3. **Сетка точек** 16 px (как бумага в клетку/светокопир).
4. **Сцена-подиум** внизу: тёмный пол, пиксельные борозды, плинтус.
5. **Кресло наблюдателя** слева (портретное, тёмно-фиолетовое, пиксельное; маска 34×32).
6. **Силуэт в шляпе** справа в тени (маска 16×26) — отсылка без лица.
7. **Табличка «ХОД N»** в правом нижнем углу — как карточка дела.

### 7.7. Пиксель-портреты «по мотивам» (вместо реальных фото)
Соберём вручную масками 24×24 (3–4 цвета + акценты): **наблюдатель в шляпе**, **агент»,** тёмный антагонист**. Используем:
- как **фоновые «кадры»** главы (крупный портрет на 40% прозрачности за светом, по 1 на главу);
- как **аватар в меню заголовка** (без имени шоу);
- как **иконку босса** перед его уровнем.
**Не** вводим фотографии из сериала; всё нарисовано кодом. (Надпись на примерах в макетах — это концепт, тексты утвердим.)

### 7.8. HUD
Полоса сверху ~38 CSS px, на `#1d1740`:
- **ОЧКИ** (крупно, моно-шрифт) · **СЛЕД / КОМБО** (×1…×8) · **ЖИЗНИ** (маленькие карточки) · кнопка паузы.
- Вариант «маленького HUD» для узких телефонов — иконки + числа; подробно — §14 (адаптив).

### 7.9. Экраны
- **Title**: имя игры «АЛИБИ», «Играть» / «Настройки» / «Как играть»; портрет-маска и силуэт на сцене; мяч медленно падает на прожекторе (анимация).
- **Как играть**: 3 строчки, пиктограммы (drag, тап, пауза).
- **Пауза**: затемнение, «ПАУЗА», «Продолжить / Меню».
- **Межуровневый**: «ХОД N ЗАКРЫТ» + счёт + «Ход N+1»; после главы — «Серия N: ЛИСТ ЗАКРЫТ» с голой сценой.
- **Проигрыш** (главный вау-экран): сильное затемнение, панель, **красная ухмылка (смайлик) капающая кровью**, крупно «ДЕЛО ЗАКРЫТО», строки под ним, итоговые очки/рекорд, кнопки **«НОВОЕ ДЕЛО»** / **«МЕНЮ»**. См. `preview-gameover.png`.

## 8. Главы и мир (нарратив отсылок)

**Структура: 3 главы × 6 уровней + босс** = **18 обычных уровней + 1 босс**. Плюс финальный босс-уровень Джона (20-й «часовой» уровень не нужен; Босс — 6-й в главе 3). Итого **19 игровых уровней**.

| # | Глава | Палитра/акцент | Фон-сцена | Порядок уровней |
|---|---|---|---|---|
| 1 | **«Дело о выбеленных стенах»** | тёплая бумага, бордовый | прожектор + кресло | 6 промежуточных, паттерны: звёзды, сердце, «клетка», радуга из улик |
| 2 | **«Дом без окон»** | холодный синий, ламповый зелёный | силуэт в проёме, двери | 6 |
| 3 | **«Ход в красном»** | кровь, уголь, золото | театральная сцена, занавес | 5 + **босс** |

- Внутри уровня — **паттерны из улик**: строчные надписи псевдо-нот, «печать», «пирог», «лицо» (из кирпичей, без лиц персонажей из фото — только формы).
- Между уровнями — краткая строка: «ХОД 1 · СЛЕД ВЕДЁТ К ТЕАТРУ» и т.п. (всё это в `strings.ru.ts`, легко правится).
- Эпилог после босса: короткий экран «Ты был прав. Но начни сначала» (без прямого наименования шоу).

## 9. Босс-уровень «Кровавый Джон»

Отдельный уровень в конце главы 3 (`type: "boss"`). Классическая, но по-мобильному честная механика:

- **Босс** — пиксельное **красное лицо-ухмылка** в верхней части поля (48×48), со своей HP-полосой в HUD (`ДЕЛО: 30/30`), и **щитом из кирпичей** — 2–3 ряда, частично раскладка `X` (неразрушимые).
- **Атаки босса** (в подпорядке, каждые ~4–6 с, хорошо телеграфируются за 0.6 с миганием):
  1. **«Улыбка»** — из глаз вылетают 3–5 маленьких снарядов-капель, веером вниз (их можно сбить кирпичами; попадание снаряда в ракетку = потеря жизни? — **нет: штраф-«тряска» и −30 очков**, чтобы не было 8-bit-несправедливости; можно сделать опцией «честный бой»).
  2. **«Взгляд»** — луч из глаз; поле на 1.2 с заливается красным и активирует «липкие ноты»? → **не перегружаем**: луч только меняет прозрачность сцены, без урона, как предупреждение.
  3. **«Шёпот»** — телеграф, затем в течение 3 с перемещает одну стенку? — **нет** (нарушает арканоид). Оставляем 1.
- **Как победить**: разбить кирпичи-щит **и** наносить урон боссу ударами мяча по его лицу (лицо имеет «голову» и «шею» — удар по шее бьёт больнее — необязательно). Простой и понятный: каждый удар по лицу −1 HP (и удар по щиту может «рикошетить» в лицо = −1).
- **Проигрыш на боссе — особая концовка**: экран проигрыша всегда показывает ухмылку, но с босса — с добавкой «Он знал, что ты уже здесь».
- **Вибрация/звук**: на попадании в лицо — низкий тон и тряска экрана (2 px, 120 мс), на проигрыше — протяжный тон и остановка мира.

## 10. Звук

- **Web Audio**, синтез (без файлов на старте): короткие blip'ы (140–900 Гц квадрат/треугольник), «стена» — глухой, «ракетка» — упругий, «кирпич» — по типу, «потеря мяча» — падающий тон, «ухмылка» — низкий хорд.
- **Unlock**: AudioContext создаётся при первом жесте (обязательно на iOS). До этого — ничего.
- **Настройка** громкости / mute, по умолчанию 60%, сохраняется.
- Позже: заменить «ударные» синтезированные на короткие сэмплы, если захочется.

## 12. Производительность и качество

- **Бюджет**: ≤ 1000 частиц на экране, ≤ 120 кирпичей, ≤ 6 мячей (если бонусы позже). Render: статика фона предрендерится один раз в `ImageBitmap`/offscreen canvas при смене главы; в кадре — только `drawImage` фона + динамика.
- **Целевые**: 60 fps на iPhone SE (2020) и среднем Android; 120 fps где поддерживается. На слабом устройстве — деградация: меньше частиц, отключение тряски.
- `devicePixelRatio` не применяем к пиксельной сцене (см. §2).
- **Тесты** (Vitest): физика (угол отскока, sweep), валидатор уровней, комбо/счёт, fitScale(). **E2E** — опционально Playwright (запуск на iPhone-эмуляции).

## 16. Публикация на GitHub Pages

**Цель**: игра открывается по адресу вида `https://<логин>.github.io/<репозиторий>/` с телефона.

- **База пути**: для Pages в подпапке `vite.config.ts` → `base: './'` (относительные ассеты; работает и в корне, и в подпапке). Для своего домена — `base: '/'`.
- **Статика**: `npm run build` → `dist/` (index.html + assets). Никаких серверных частей.
- **Авто-деплой**: `.github/workflows/deploy.yml` — на push в `main`: `npm ci` → `npm run typecheck` → `npm run test` → `npm run build` → `actions/upload-pages-artifact` → `actions/deploy-pages`. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
- **Кэш/CDN**: Vite хэширует имена ассетов — кэш браузера безопасен.
- **Что публикуем**: только `dist/`. `docs/` **не** публикуем (там этот документ и генератор превью — в бандл не попадают).
- **PWA (опционально, после v1)**: manifest + service worker → «Добавить на экран», фуллскрин без адресной строки на телефоне. Рекомендую включить в M4.5.
- **Локальная проверка прод-сборки**: `npm run build && npm run preview`.

Порядок первого деплоя (сделаю сам, когда будет репозиторий):
1. `git init`, `.gitignore` (node_modules, dist), первый коммит.
2. Создать репозиторий на GitHub, `git remote add origin …`, `git push -u origin main`.
3. Settings → Pages → **GitHub Actions**.
4. Дождаться зелёного workflow → открыть ссылку с телефона.
